# 速度优先版必要修缮：visibility-fast-v8

保留旧 Strong、V6 及其配置源码不变，新增 V8。目标是低计算量下接近 Strong，不追求以更大搜索预算提升胜率；不训练、不加载模型。

## 三项修缮

1. **剪枝正确性**：仍按有效花色和未知牌之间的相对顺序减少候选，但把当前墩中的牌加入分界，并要求合并候选具有相同的当前赢墩结果。无将中 Q 已出、手持 J/K 时，必须同时保留输墩与赢墩动作。以前各墩的 Q 已离开牌局时仍可约简。Joker 指定花色及 Misère 不合并。
2. **少量末家例外**：唯一合法动作仍立即返回；普通末家仍通常采用 Medium。仅在正常合约接近成约、最后三张，或具备接管首引兑现长套的信号时，保留基准与一个不同赢墩结果的动作，最多两候选、两样本。Misère 的末家保留原专用规则。
3. **加权风险**：使用有效样本数 `(sum w)^2 / sum(w^2)` 估计标准误，不再把权重极不均衡的样本当作等量独立信息。有效样本数低于 1.5 时不改变基准动作。固定改善门槛仍为 8，标准误系数仍为 0.75；这是启发式稳定措施，不是正式置信检验。

## 保持的小预算

- 叫牌仍直接使用 Medium。
- 弃牌仍是启发式前三组加基准，四个隐藏牌样本，最多十六次续演。
- 普通出牌仍在手牌至少七张时用四样本，否则八样本。
- 仍完整续演至本副结束；没有引入短程估值、预训练、扩大对手池或更深搜索。
- 对手模型、原采样器及整场效用函数保持不变。约简仍可能忽略牌面信号；少样本覆盖不足仍是接受的速度折中。

## 小规模验证

使用旧速度版相同牌组：

| 对局 | 场数 | V8 胜:负 | 旧 V6 对照 |
|---|---:|---|---|
| 对 Medium | 20 | 12:8 | 13:7 |
| 对旧 Strong | 8 | 3:5 | 4:4 |

没有非法动作或轮次上限截断。样本不足以证明统计等价或强度差异；没有按这些结果追加搜索量或继续调参。

同一观察语料、独立预热、每阶段最多十六次决策，共四十一次观察：

| 版本 | 按观察数加权的平均决策耗时 |
|---|---:|
| 旧 Strong | 63.81 ms |
| 旧速度版 V6 | 5.52 ms |
| 修缮版 V8 | 4.73 ms |

这只是该语料上的成本，没有证据表明新增修缮提高了计算负担，也不把它解释为普遍加速保证。完整配置、计时、P95 和程序集指纹在 [fast-v8-results.json](fast-v8-results.json)。

## 运行

```sh
dotnet run --project FiveHundredLab -c Release --no-build -- bench \
  --a visibility-fast-v8 --b strong-v1 --pairs 2 --seed 2301001 --out /tmp/fast-v8-check
```

`visibility-fast-v6` 仍可显式选择用于历史对照；默认切换到 V8。新增两个策略文件记录在 `frozen-profiles-v2.json` 中，不改写旧冻结清单。

最终验证：完整构建 0 警告、0 错误；456 项测试通过，无跳过；本轮 28 场对战全部通过逐动作重放；41 个冻结源码/模型文件的指纹检查通过。

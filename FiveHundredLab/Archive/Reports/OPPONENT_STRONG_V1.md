# 自适应 Strong 三阶段 v1（可配置规则）

新增策略，原 Strong 和六种已有 bot 不改。三阶段均保留原 Strong 的候选筛选、Monte Carlo 置信改善选择及**完整叫牌竞叫续演**；没有将根节点叫牌替换为规则版 Strong 的启发式决策。Medium 只提供基准候选及常规续演模型。默认8个隐藏牌样本、12组弃牌候选、改善门槛8、标准误系数0.75。

| 注册名 | 功能 |
|---|---|
| opponent-strong-bidding-v1 | 在线估计每位玩家的保守／常规／激进叫牌倾向，抽样用于续演 |
| opponent-strong-belief-v1 | 加入风格相关的叫牌似然，调整隐藏牌样本权重 |
| opponent-strong-play-v1 | 再学习普通合约中保牌／接管队友首引的偏好 |

完整运行名另含搜索预算。可用 `Profiles.CreateForRules(name, seed, rules)` 将同一个规则快照交给新bot和引擎，也可用 `new OpponentStrong(seed, stage, options, rules)`。不传rules使用原默认规则。显式配置不匹配会拒绝，不静默切换到另一套规则。

第三阶段完整机制现以 `Adapt` 命名封装（`Adapt` / `adapt-v1`），原阶段注册名继续有效。20组随机阵容配对比较见 [报告](adapt-vs-strong-20-v1/REPORT.md)。

## 第一阶段：叫牌风格

每个座位独立保存三种模型权重，初值 `[0.2,0.6,0.2]`，不对自己建模。保守模型在常规建议上减少叫牌阶数或Pass；激进模型尝试提高一阶或用较宽松牌力门槛竞争，所有建议都来自合法叫牌列表。这些是粗粒度模型，不能概括每个人的所有行为。

默认在自身Bid/Discard/Play时处理新观察到的公开动作，不会在模拟里更新真实信念。每轮保存最初叫牌时自己的十张牌，生成8份假设原始分配，积分计算别人已发生动作的模型似然；**不读取真实对手手牌、底牌、审计牌谱或发牌种子**。公共后验接口 `ObserveAuction`/`ObservePublic` 也可供未来界面转发合法公开观察。

每位玩家每副最多计两条叫牌证据。弱证据的幂为0.2，旧权重按0.97/0.03向先验衰减，再用16%原先验保护后验，避免少量证据把某类型排除。无区分力的证据不会将初始先验推向均匀分布。该更新是带遗忘和保护的启发式贝叶斯混合，不是精确后验。

一次样本续演中，每人抽取一次策略类型并固定到结束；比较候选时复用隐藏牌分配、类型和随机数，避免每一步重新换“性格”。自己的续演保持常规模型。

## 第二阶段：风格影响牌分布

使用本副开始前的叫牌权重作为先验，按该假设手牌下实际叫牌的似然计算世界权重；同时按同一联合模型抽取该世界里的风格。不会把当前副已经更新的后验再当先验使用，也不再乘上旧采样器的Medium叫牌权重。

普通非定约者的原始十张牌可由假设剩余手牌和公开已出牌拼回。取底后的定约者原始十张牌不能据其剩余牌直接恢复，所以此时排除其叫牌似然，而不是把换底后的牌当成原始牌。样本有效数不足时温和压缩似然权重（最多降至1/8幂），不把尖锐的少样本权重当成可靠推断。

采样仍是满足公开约束的随机可行分配，并非精确、均匀后验。Joker公开命名、双Joker、六张底牌等沿用规则版采样约束。

## 第三阶段：有限的出牌偏好

当前只学习普通合约中“保留搭档赢家／接管首引”这一维度，没有顺带推断玩家的总体水平、垫牌信号体系或Misère防守水平。

当实际牌和该玩家后来公开打出的另一张牌证明他当时有两种不同的合法选择时，才给偏好提供证据。没有中途抽牌，所以后来打出的牌在该较早时点已在其手中。还要通过当时的规则过滤，强制超吃等情况不会被算成主动接管。

尚不能判断的旧动作会在获得新公开证据后重新检查；每动作只学一次，每玩家每副最多两次，证据幂0.3。续演中仍按整次样本固定策略。模型不查看未公开的后来手牌。

## 规则及生命周期

- 配置读取与引擎共用 `RuleConfiguration.Load`；续演读取实际叫牌位置、单轮Inkle、Pass、底牌数量、首攻、参与人数、亮牌时机、Joker及计分/封顶规则。
- 所有模拟拥有自己的规则上下文和手牌副本。基准和其他玩家只看到其角色应见的牌，没有把完整世界传进其Observation。
- 没有调用可见牌谱的学习回调；整副结束后如果外部服务没有再次提供合法观察，最后几个未观察到的动作不会被学习。这是覆盖不足，不是用审计牌补猜。
- 目前以座位识别玩家，适合一场比赛内固定玩家。换人、换桌需新建bot或调用 `ResetLearning()`；换规则需新建绑定该规则的bot。重置学习不承诺重置搜索RNG，完全复现应新建同种子实例。
- 主动放弃可选Joker预命名，仍正确处理已公开命名。未实现的规则由共同加载器拒绝。
- 新代码由 `frozen-profiles-v5.json` 单独冻结；原有策略源码不变。

## 验证方法与当前结论

`TestOpponentStrong`验证：权重可反转、座位分离、无证据不漂移、80次公开叫牌流、重复观察去重、旧Strong搜索复制对照、当前副证据不重复计入、换底手牌边界、延迟出牌证据及强制超吃反例、三阶段×六配置的18次运行与重放，以及同种子复现。

全配置/复现测试为快速反馈使用2样本/3弃牌候选，属于明确不同预算；实战检查使用默认8样本/12候选。固定Medium消融在原默认规则下一副同种子测试中与旧Strong动作和分数完全一致；这不是所有规则上逐动作等价的证明。

固定似然的受控分类测试可观察到预测改善，但它不等于真实牌局识别。80个随机牌局的保守脚本玩家公开动作流中，固定先验平均NLL约0.908，自适应约0.919（越低越好），**本轮未显示预测收益**。该流中实际手牌仅由合成演员用于选动作，学习器没有收到它。此结果说明现有信号较弱、模型与样本噪声仍需评估，不能宣称它已可靠识别真人风格。

默认预算实战加入固定Medium、固定混合两种消融，再与三阶段比较。每模式仅一对同牌序交换队伍，保守脚本队友对阵常规/激进脚本对手；不是随机抽取的真人群体，也不足以判断胜率差异。详细结果保存在 `opponent-results-v1/`，不按小样本宣称改进。

## 运行

```sh
dotnet run --project FiveHundredLab -c Release -- bench-mixed \
 --a opponent-strong-play-v1 --b medium-rules-v1 \
 --rules FiveHundredRules/presets/legacy-au-4p-v1.json \
 --pairs 1 --out /tmp/opponent-mixed-new

dotnet run --project FiveHundredLab -c Release -- opponent-check \
 --rules FiveHundredRules/presets/legacy-au-4p-v1.json \
 --pairs 1 --seed 2707001 --max-rounds 60 --out /tmp/opponent-check-new

dotnet test TestBots -c Release --filter FullyQualifiedName~TestOpponentStrong
```

`opponent-check`输出完整可重放牌谱、每场权重与更新次数、耗时。固定Medium参考通过 `learn:false,fixedMedium:true`，固定混合参考通过 `learn:false` 构造。所有输出使用新目录，避免覆盖历史记录。

# 第二阶段：公开信息下的当前墩证明

新增实验 bot [StrongTacticalBot](../../FiveHundredLab/Bots/FiveHundred/StrongTacticalBot.cs)，profile 为 `strong-tactical-v1`。旧 Strong、StrongPlus、All32 和第一阶段 Structured 的源码、参数均保持不变。没有自动替换正式 bot。

## 策略与适用范围

搜索基准为 All32：叫牌、弃牌、出牌均为 32 个隐藏牌样本，弃牌仍为旧的前 12 组加 Medium 基线，默认改选门槛 8、标准误系数 0.75，继续由原 Medium 续演。本轮仅在根节点出牌前加入独立的证明层：

- **Misère 防守方**：若一个合法动作在所有可能的当前墩应对下都让庄家得墩，直接采用该动作。只要庄家得一墩，合约即失败。
- **Misère 庄家队**：排除那些必然让庄家得墩的动作；至少保留一个替代动作才裁剪，避免删空候选。四人零墩时，庄家搭档与庄家站在同一边。
- **普通合约**：仅在本队再取一墩即可确保保约或破约时，将候选限制到可证明本队必取当前墩的动作。其余动作仍由原搜索比较；不能证明时保留全部动作。

只使用手牌、自己知道的弃牌、公开出牌和明确摊开的手牌。未知手牌用剩余牌的超集处理，允许未知玩家作出甚至不符合跟牌要求的应对；这会漏掉一些可证明的机会，但不会依赖猜测的暗牌分配。摊开手牌使用当前规则计算合法动作。证明仅处理当前墩，不宣称求解整副牌。

参与人数由合约配置决定；不把默认三人 Misère 硬套到四人变体。显式配置下的假想应对使用分离的规则状态，保持跟牌、Joker 声明、出牌历史和当前座位的语义，不修改传入观察。每次决策至多访问 8,192 个证明节点；达到上限即放弃尚未完成的证明。默认与显式规则配置均支持相同的构造参数及 `FromConfiguration` 接口；显式配置的叫牌仍为旧启发式。

## 预先固定的验证设计

[metadata.json](metadata.json) 在实战前写入策略哈希、预算和计划，无筛选后调参：

| 比较 | 纯队 | 与 Medium 搭档 | 总计 | 用途 |
|---|---:|---:|---:|---|
| Tactical / All32 | 8 对 / 16 场 | 8 对 / 16 场 | 32 场 | 主比较：隔离证明层 |
| Tactical / Strong | 4 对 / 8 场 | 4 对 / 8 场 | 16 场 | 次要参考：同时包含预算增加 |

每对使用相同发牌种子、起始庄家，交换双方队伍；每场每个座位分别创建 bot。混合队形式为 Tactical + Medium 对对手 + Medium。固定新种子块 `19119001`，每对增加 `7919`，混合队和 Strong 参考组使用分离偏移。四路并行，200 轮上限，逐场存盘。主比较和参考组不合并推断。

## 实战结果与结论

全部 48 场正常结束，无非法动作、执行错误或截断，全部通过完整重放。冻结源码和模型共 76 项校验通过。

| 比较 | Tactical 胜–负 | 胜率 | 成对全胜 / 平分 / 全负 | 保守 95% 区间 | 成对符号检验 p |
|---|---:|---:|---:|---:|---:|
| 对 All32，纯队 | 8–8 | 50.0% | 0 / 8 / 0 | 28.9%–71.1% | 1.0 |
| 对 All32，Medium 搭档 | 10–6 | 62.5% | 2 / 6 / 0 | 30.0%–84.7% | 0.5 |
| 对 All32，合计 | 18–14 | 56.25% | 2 / 14 / 0 | 见分组区间 | — |
| 对 Strong，纯队 | 4–4 | 50.0% | 0 / 4 / 0 | 16.7%–83.3% | 1.0 |
| 对 Strong，Medium 搭档 | 4–4 | 50.0% | 0 / 4 / 0 | 16.7%–83.3% | 1.0 |
| 对 Strong，合计 | 8–8 | 50.0% | 0 / 8 / 0 | 见分组区间 | — |

主比较有微弱正向线索，主要来自两对混合队全胜；没有统计显著的胜率提升证据。纯队主比较和全部 Strong 参考对均为换边后各赢一场，说明这一小批种子中发牌、座位影响很大。不能将参考组的五五开与第一阶段不同种子的 59.4% 相减来判定退步，也不能据此确认无下滑或等价。

全部实战共有 438 副普通合约、5 次全 Pass 重发，**没有 Misère 或 Open Misère 合约**。因此这批胜率只检验了普通合约干预，Misère 的收益由定向场景与正确性测试支持，尚缺实战覆盖。

6,420 次 Tactical 出牌查询中，证明层介入 61 次（0.95%）：保约 29 次、破约 32 次；总计 242,545 个证明节点，11 次达到节点上限。离线相同输入、相同种子的动作对比中，61 次介入有 28 次改变建议（保约 15 次、破约 13 次），另外 33 次与原 All32 的建议相同。例如在 `reference-mixed/pair-000-leg-0` 第 20 副的对比中，原搜索建议黑桃 7，证明层选择 Joker 确保关键破约墩。此类变化体现了“先兑现确定收益”的策略，不能单凭它归因整场胜负。

与 All32 同场的纯队组平均出牌耗时为 132.4 / 132.5 ms，混合队组为 167.9 / 164.7 ms（Tactical / All32）。并行实战没有显示明确的整体加速；局部必破场景的显著省时没有在普通合约为主的随机对局中充分体现。预算上限使额外开销受控，但这些计时不是独立性能基准。

本阶段保留独立实验版本，**不升级默认 bot**。优先保留已经明确修复的公开必破机制；普通合约的强制保约/破约候选裁剪尚需作为独立因素与 Misère 判断拆开验证，以检查安全优先是否牺牲了其他得分机会。后续若继续验证，应加入有代表性的 Misère 定向对局，而不是只追加同类随机对局；同时保持一个原 All32 对照。当前没有启动下一轮调参或训练。

## 行为与正确性检查

17 个固定体验场景 × 4 个随机种子 × 4 种 bot，共 272 次查询，动作均合法。Tactical 与 All32 的 16 次叫牌、12 次弃牌全部一致；40 次出牌中改变 4 次，均为 `open-misere-forced-bust`。

| 版本 | 体验检查失败项 | 其中公开必破严重项 |
|---|---:|---:|
| Strong | 12 | 4 |
| All32 | 9 | 4 |
| StrongPlus | 5 | 0 |
| Tactical | 5 | 0 |

这里是断言失败项计数，同一场景的四个种子不代表四类独立问题。弱牌开叫和无将挡张建议项仍然失败，本轮没有修改这些策略。Tactical 与 StrongPlus 在该审计得分相同，不意味着二者策略等价或胜率相同。

必破场景中，All32 选择方块 4，Tactical 选择红桃 5；后者经过 183 个证明节点确认可使庄家得墩。四个种子均有同样改变。审计中的耗时约为 All32 195–229 ms、Tactical 0.11–0.36 ms，仅说明这一局面能够省掉搜索；并行环境下的局部计时不能当作整场提速比例。

新增 7 项测试覆盖保约/破约阈值、四人 Misère 搭档立场、证明预算耗尽、已失败合约不介入、公开必破、与 All32 的叫牌/弃牌等价、工厂入口，以及默认与六份配置下运行和重放。另用随机小手牌枚举所有实际应对，核对证明成立时没有反例、规则对象未被修改。完整测试共 532 项通过。

## 如何阅读结果

最终胜率和行为统计由 [summary.json](summary.json) 生成，重放及冻结源校验见 [validation.json](validation.json)。每组保存成对全胜/平分/全负、按对抽样的 bootstrap 区间、保守 95% 区间和符号检验。保守区间用成对全胜/全负各自的 Clopper–Pearson 区间经 Bonferroni 合成；合计 bootstrap 按 pure/mixed 分层、按对抽样。小样本的 bootstrap 可能退化，不应单独依赖。

每场记录所有证明查询、节点数、达到预算次数、介入原因和裁剪候选数。**介入不等于相对 All32 改变了动作**：All32 也可能原本就会选中某个证明动作。真实对局发生分歧后，后续输入和随机数消耗也会不同；不能将后续每个不同动作都归因于战术改进。

另用 [离线复盘工具](review/Review.cs) 在每次真实介入的公开局面中，新建一对相同种子的 All32/Tactical，比较是否改变建议动作。种子为 `gameSeed + 97*(seat+1) + 7919*(playIndex+1)`，均按整数溢出语义处理；不执行建议，不增加实战对局。完整原牌局同步脚本重放并逐字段核对。明细在 `results/intervention-review.json`。这是隔离当前根节点机制的诊断，不还原 All32 若从整场开局参加时的随机数状态，也不能推断某次改变造成了多少分或几场胜利。

局限包括：未知手牌超集偏保守；不推断历史缺门；节点预算可能使后排候选来不及证明；普通合约保约优先可能牺牲高风险的满贯机会；没有把根节点证明加入所有续演者；规则变体只验证功能，胜率实战仅用默认规则。没有在线学习或预训练。

## 复现

仓库根目录执行，需 .NET 8、Python NumPy/SciPy：

```sh
dotnet build experiments/public-tactics-v1-20261109/Study.csproj -c Release
dotnet experiments/public-tactics-v1-20261109/bin/Release/net8.0/Study.dll experiments/public-tactics-v1-20261109/results audit
dotnet experiments/public-tactics-v1-20261109/bin/Release/net8.0/Study.dll experiments/public-tactics-v1-20261109/results validation
python3 experiments/public-tactics-v1-20261109/analyze.py
dotnet build experiments/public-tactics-v1-20261109/review/Review.csproj -c Release
dotnet experiments/public-tactics-v1-20261109/review/bin/Release/net8.0/Review.dll experiments/public-tactics-v1-20261109/results
python3 experiments/public-tactics-v1-20261109/analyze.py
dotnet test TestBots -c Release --logger 'trx;LogFileName=public-tactics.trx' --results-directory /tmp/tactical-validation
python3 experiments/public-tactics-v1-20261109/verify.py
```

已完成的同版本任务会跳过；程序集版本改变时应使用新结果目录，不混入旧数据。压缩牌谱包含完整暗牌，仅用于离线复盘。第一阶段数据不混入本轮胜率。
